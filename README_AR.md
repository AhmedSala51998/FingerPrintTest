# الدخول ببصمة الإصبع أو Face ID

المشروع جاهز بـ PHP وMySQL وWebAuthn، ومجلد vendor موجود بالفعل.

## التشغيل

1. ارفع محتويات المشروع إلى موقع يعمل بـ HTTPS.
2. احتفظ ببيانات قاعدة البيانات الصحيحة في config.php. لم يتغير تركيب الجداول أو database.sql.
3. لو الجداول موجودة عندك بالفعل، لا تحتاج إلى استيراد قاعدة البيانات مرة أخرى.
4. افتح register.php من Safari على الآيفون، اكتب الاسم واضغط تسجيل بصمة الإصبع أو Face ID، وأكمل نافذة Apple لحفظ مفتاح المرور.
5. افتح index.php على نفس الدومين واضغط زر الدخول، ثم اختر مفتاح المرور ووافق على Face ID أو Touch ID.

Face ID أو Touch ID ورمز قفل الجهاز يجب أن يكونوا مضبوطين على الجهاز. لحفظ مفاتيح المرور باستخدام Apple قد تحتاج إلى تفعيل كلمات السر وسلسلة المفاتيح في iCloud. استخدم نفس الدومين في التسجيل والدخول: example.com وwww.example.com ليسا نفس المصدر. لا تضع https:// أو مسار مجلد في RP_ID؛ تركه فارغًا يستخدم دومين الموقع.

رابط HTTP مثل http://192.168.1.5 لا يعمل على الآيفون. localhost يُقبل للتطوير على الكمبيوتر نفسه فقط. الموقع لا يحصل على صورة الوجه أو بصمة الإصبع؛ الجهاز يوقّع التحدي، والخادم يتحقق من التوقيع بمفتاح عام. الجهاز قد يسمح برمز القفل بدل البصمة، ولا يمكن للموقع إجباره على Face ID وحده.

## الإصلاحات

- تصحيح ترميز challenge وuser.id ليصل إلى المتصفح بصيغة Base64URL سليمة.
- تسجيل مفتاح مرور قابل للاكتشاف باستخدام مُصدّق الجهاز واشتراط تحقق المستخدم.
- التحقق من دعم المتصفح وHTTPS وإظهار رسالة واضحة عند عدم الدعم أو الإلغاء.
- إنشاء المستخدم فقط بعد نجاح التحقق، مع حفظ المستخدم والمفتاح في معاملة واحدة؛ إلغاء التسجيل لا يضيف مستخدمًا فارغًا.
- تحديات تنتهي بعد خمس دقائق وتُستهلك عند التحقق، مع فحص مصدر الصفحة وتغيير معرف جلسة الدخول.

تم اختبار التوقيعات والتحديات والتحويلات برمجيًا؛ يلزم تجربة Face ID الفعلي على آيفون بعد رفع المشروع إلى HTTPS.
